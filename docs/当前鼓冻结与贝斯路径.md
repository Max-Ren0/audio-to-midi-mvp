## 当前贝斯实际实现

原MP3 → Demucs htdemucs_6s分出bass.wav → 单声道/8000Hz → librosa pYIN每16ms估计一个基频 → 转MIDI音高、补短空隙/平滑/切音符 → 写入Fingered Electric Bass音色（代码Program33，即GM第34项）。没有调用音乐服务商API，也没有训练新模型。

真实参数（`src/audio_midi/contour.py`）：

- 音高搜索32–261Hz，2048采样点分析窗口、128采样点步长（16ms）。
- 保留有音高、概率≥0.2且能量超过max(0.001,本段最大RMS×0.025)的帧。
- 频率换算到最近的MIDI半音；同音两侧的小空隙≤35ms才补齐，五帧中值平滑。
- 音高变化或音频起音触发切分；最短音符80ms。同音反复弹奏依赖起音检测，不能只靠音高变化。
- 通用清理后写MIDI。当前该轨没有模型输出力度，导出默认力度80；不表示还原了原演奏力度、滑音或弯音。

当前保留A方案Demucs+pYIN，51个预测/36个标准，匹配18，误报33、漏检18，F1=41.38%。B方案SW+pYIN为12/37/36，F1=32.88%，因此未替换。另一BasicPitch贝斯实验也未胜出。评分证据：`outputs/two-methods/逐轨两法本地清单.json`。当前六轨中的贝斯保留该A方案，不是新做过专项强化的版本。

这是单音音高跟踪路线：低频谐波可能导致八度误判、分离串音可能变成假音符、缓慢起音可能偏迟、相同音高连弹可能粘连。以上是方法风险，尚未逐音证明它们在本曲各占多少。下一步若优化贝斯，应先拆开音高错误、起音错误、重复音切分和误报来源，再决定换分离或转谱器。
