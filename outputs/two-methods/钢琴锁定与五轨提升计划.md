# 钢琴固定B，五轨质量提升计划

日期：2026-10-16。用户已指定钢琴固定B：BS-Roformer SW钢琴源＋Transkun。当前阶段路由已是piano=sw（config/two-methods-stage.json）；本轮不改历史配置/模型/产物。不因为其他轨分数变化重新选钢琴。此决定不表示所有歌曲钢琴都已验收。

## 全局流程和核心判断

输入 → 每类专用分离（先把声音分干净）→ 音符转写（音高/起止）→ 乐器归类和可信度检查 → MIDI/试听 → 逐轨验收。

目前吉他总轨没有分木/电，弦乐从other残留中筛；贝斯用音高曲线拼音符，鼓用通用多乐器模型。这些是实际实现事实。串音、模型域偏移、错类别或切分延迟属于待测成因，单凭参考MID无法证明哪一个是主要分离故障。

阶段稿钢琴268匹配/269预测/269标准；其余五类合计77匹配/239预测/225标准，micro F1=33.1897%。因此整体68.86%由钢琴大量贡献，不能当五轨已接近可用。

## 每轨最大化改善路线

### 木/电吉他：先解决两把吉他混在一起，再比较转谱

1. 真正取得木/电专用音频。分别比较MVSep API66/81的混音直出和从总吉他提取；这两个是同一专用模型的两种流程，不能称全球前二模型。官方文档：https://mvsep.com/en/full_api 。目前未配置key，均未执行。
2. 每份分离音频分别用现有YourMT3和乐器无关的BasicPitch生成预测，形成“2种输入×2种转谱”的可归因对照。BasicPitch官方支持复音，推荐一次一个乐器，但不自带木电分类：https://github.com/spotify/basic-pitch 。它只是不同候选，不承诺胜出。
3. 只在声源确实已隔离且有声音存在性证据时，给乐器无关转谱器写入目标类别；隔离失败保留不确定，不能把通用模型所有音符一律改名。YourMT3原类别输出作对照，检测是否因类别过滤丢音。
4. 木电合并评分仅用于区分“音符已对但类别不对”和“音符本身没认出”；最后必须分开验收。保留扫弦内细微先后、连奏/重复音，避免硬量化抹平。

### 贝斯：把找音高和找起音拆开

1. 固定同一贝斯源，对照现有pYIN与torchcrepe；后者有Viterbi/periodicity/silence处理，但不保证本曲胜出：https://github.com/maxrmorrison/torchcrepe 。pYIN适合清晰单音源：https://librosa.org/doc/dev/auto_tutorials/01-intro/03-f0.html 。
2. 现实现8kHz、2048帧长（256ms窗）、128hop（16ms）、最短80ms，音高轨迹再切分。这些参数值得测快速起音/同音重复；中心窗不等于固定256ms延迟。独立用音频攻击包络分音符，以稳定基频估音高，检查同音重复、短音、八度与关音。
3. 以音频而非标准估计延迟；所有候选同一时间原点。先前简单300ms起音回溯未胜基线，不重复当成新解法。
4. 更好bass ensemble可作为分离轴对照，但SW bass当前反降，不能预设分离榜高必然转谱更好。历史BasicPitch bass26.67%也低于pYIN41.38%，不能再把未变的同一方案叫升级。

### 鼓：优先补漏检和鼓件分类

1. 选同一鼓源，以现有YourMT3为基线，比专用鼓转写；另设鼓ensemble与当前源对照。先按底鼓/军鼓/踩镲/通鼓/镲检查漏音集中在哪里。
2. 专用ADTOF已在旧源实测53.71%，未胜56%；只有在新输入/明确解码变化后才值得对照，不预设更好。原仓库含非商业许可，限定研究，不能直接作为商用默认：https://github.com/MZehren/ADTOF 。
3. 对每鼓件分别调起音阈值和相邻击打去重，保留轻击、滚奏和同时间不同鼓件；用开发集选参数，冻结后验证，不按标准补节奏。
4. 粗分类模型不能臆造开闭镲/具体镲片等细GM键；细GM不足明确限制或引入可输出细类的候选。统一拍点只作可选编辑，不强制吸到网格。

### 弦乐：先建立真正弦乐源，再抑制多报

1. 用专用bowed strings（API52，BS Roformer与gilliaan候选）替代other残留默认来源；官方接口已核实，实际尚未运行：https://mvsep.com/en/full_api 。
2. 对同一专用源比现有YourMT3与BasicPitch等复音候选；弦乐可能多声部，不能用单音pYIN代替。门槛包含持续谐波、包络和音量，不凭长音自动判弦乐。
3. 有可靠持续声证据才保留低起音弦乐候选，同时测真实弱弦乐被误删数量；钢琴与弦乐可能齐奏，不能见同音就删弦乐。
4. 先抑制残留导致的多报，再验证长音起止/和声音符；至少补有较多弦乐的真实片段。当前仅7个标准起音不能稳定选冠军。

## 执行顺序和验收

1. 已完成：锁钢琴B；不改产物的诊断。待完成：人工核对音频/改编标准是否同编配，并用起中末音频锚点检查共用同步；没有干净原始乐器WAV，不计算伪SDR。
2. 无API也可做：贝斯“音高/攻击拆分”小样，鼓按件错误统计，木电合并类别诊断和独立标注短样。先解决可观测问题，避免只等服务。
3. API可用后：优先木电与弦乐专用源，保留原WAV，再固定转谱器比较分离、固定分离比较转谱；最后才尝试带音频证据的模型融合，不能把所有预测取并集。
4. 每个乐器保留每种方法的MID、试听、评分、资源消耗和失败记录，再给一份钢琴固定B的合成版；交付不再只给合成。
5. 旧样本用于开发；新增真实歌曲按歌曲划分验证，正式5–10首、每类至少5首。每类报precision/recall/F1，五轨合计/五轨macro另列，防钢琴掩盖薄弱轨。保留50ms严格指标，并新增关音/时值、重复音、鼓细类和逐轨人工试听。
6. 想最大质量可增加人工校正，必须单列“自动原稿”和“人工修订稿”，记录工时；不伪装成自动提升。不保证90%等未测分数。
7. 本轮未执行新推理、下载模型、上传音频或付费。未来运行仍事前登记次数/资源上限，小样再全段；API只用现有额度，新增付费前告知；不干扰用户界面。冻结后独立验证本计划事实/诊断，后续实现另按冻结成果复核。
