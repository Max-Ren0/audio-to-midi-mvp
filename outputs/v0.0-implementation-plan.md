# v0.0 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. 建议由当前 agent 顺序执行，不启动子 agent；执行方式待用户确认。

**Goal:** 实现本地 MP3（≤180 秒）到按目标类别分轨的 Type 1 MIDI，并如实交付可行性实验与音乐质量评估。

**Architecture:** 文件检查与解码 → 独立模型进程 → 标准音符事件 → 片段整理及类别映射 → MIDI 导出及报告。模型实验优先于完整应用实现；模型不支持的类别明确报告，不以规则猜测填充。长任务在子进程执行以支持截止时间和中止；子进程不是独立 AI agent。

**Tech Stack:** Python 3.11 独立环境（uv 管理）、FFmpeg/FFprobe、PyTorch 候选模型、mido、numpy、pytest；具体模型和依赖由实验固定到提交及权重校验值。

**Spec:** `outputs/v0.0-spec.md`（用户已要求按该文档开始构建；其中待确认项仍需记录，未经同意不缩减七类目标）。

## Global Constraints

- 仅 MP3；实际时长超过 180 秒拒绝，不自动截断；不做前端、视频、训练、原生 DAW 工程。
- Type 1 MIDI；PPQ=480；默认 120 BPM 与 4/4，默认与估计值均有来源警告；不量化。
- 七类目标：钢琴、木吉他、电吉他、贝斯、鼓、弦乐、人声旋律。程序编号按规格的 0 基索引映射；人声必须有模型明确语义，不用 GM choir 冒充。
- 鼓通道索引 9；其他轨避开 9；力度默认 80，模型确实提供时才使用其力度。
- 初始 30 秒窗、5 秒重叠；重复容差 50 ms；短于 30 ms 或负时长丢弃；未闭合音符最长延长 10 秒且不越片段末尾。
- 单曲总处理时间≤实际时长的 3 倍；每步最多重试一次；重试共享原截止时间。
- 内存上限须实验峰值+30%回填；实验前不捏造具体值。下载与环境准备单独计时，不隐去模型载入开销。
- 不上传原始媒体、权重或密钥；每个可用阶段检查后提交与推送；正式 v0.0.0 须通过规格验收。

## Review Focus

- 扩展名为 MP3 但编码不同、损坏或时长不可信：按实际解码校验，拒绝假文件。
- 音符在接缝边缘、跨窗持续或同音重叠：统一绝对时间，不重复，不越界。
- 截止时间耗尽、内存超限及取消：终止模型子进程，不留下冒充成功的输出。
- 空结果与部分类别缺失：明确区分失败与部分结果，不把缺失当原曲不存在。
- 输出已存在、写入中断、中文文件路径：默认不覆盖，原子写入，保留用户文件。

- [ ] 记录模型载入/推理/完整流程时间与峰值内存；执行一次真实推理，复读 MIDI 检查程序、通道、音符与时间范围。

**Interfaces:** `decode_mp3(path: Path, sample_rate: int) -> AudioData(samples, sample_rate, duration_seconds)`；`NoteEvent(category, pitch, onset, offset, velocity, program)`；`write_midi(notes: list[NoteEvent], path: Path, bpm: float = 120) -> None`。

- [ ] 先写失败测试：伪 MP3、损坏、空文件、180 秒边界、超长拒绝及中文路径；运行并确认尚未实现导致失败。
- [ ] 最小实现实际格式与解码检查；不只读扩展名或容器声明；空音频和静音不调用模型。

- [ ] 实现 MIDI 写入并重新解析；用非整拍 onset 及长间隔检查秒与 tick 换算，tick 舍入误差不超过一个 tick；同 tick 先 note-off 后 note-on。
- [ ] 执行全部 pytest，通过后提交推送。

## Task 3: 分窗整理与模型封装

**Files:** Create `stitching.py`, `backends/base.py`, `backends/selected.py`, `tests/test_stitching.py`, `tests/test_backend_contract.py`。
**Interfaces:** `transcribe(samples, sample_rate) -> list[NoteEvent]`；`Window(start, end, valid_start, valid_end)`；`stitch(windows, predictions, duration_seconds) -> list[NoteEvent]`。

- [ ] 先写失败测试：30/5 窗口有效区无缺口、不重叠；首尾完整；在边界恰好 onset 只归属一次；跨窗长音不产生第二次起音。
- [ ] 实现绝对时间偏移和半开归属区；基于模型原有窗口协议避免重复分段；无法重建的跨窗长音报告限制。
- [ ] 先写失败测试：同类同音50ms重复保留较长者；30ms最短；同音重叠截断；未闭合取min(onset+10s,片段末尾)；NaN/Inf、越界音符拒绝。
- [ ] 最小实现整理规则；接入 Task 1 选定模型，明确人声支持状态及每个类别缺失情况。
- [ ] 跑全部 pytest，并用真实模型结果复查封装前后时间轴，提交推送。

## Task 5: 评测、验收与发布

**Files:** Create `evaluate.py`, `tests/test_evaluate.py`, `outputs/validation-report.md`；更新 README、CHANGELOG、CONTEXT；规格回填需保留桌面/仓库差异审查。
**Interfaces:** `evaluate(reference: list[NoteEvent], predicted: list[NoteEvent]) -> dict`；一对一匹配，同类别同音高、onset容差50ms；另算仅onset指标及已匹配误差中位数；数据清单显式标明每首实际包含类别。

- [ ] 先写失败测试：重复预测不能多次命中同一真值；错类别/错音高不命中主指标；50ms边界；空预测漏音、空真值多余音；使用最大二分匹配避免贪心少算匹配。
- [ ] 实现按类别 F1、多余/漏音数和辅助指标；明确统计口径为逐类汇总 TP/FP/FN；每类至少5首含该类样本才判定；阈值暂按规格提议0.70/0.40，最终需用户确认。
- [ ] 在5–10首真实标注歌曲上评测，记录标注人与耗时、人工修正分钟数；无数据不伪造分数。样本不存在类别的多余预测单独报告，不隐藏。
- [ ] 用户选定音乐软件后完成多轨打开/编辑检查；不得将 MIDI 库复读等同 DAW 验收。
- [ ] 执行全套检查，汇总七类分别达标与否；回填模型采样率、窗口和内存参数；未达标保留实验/候选版本。
