# MuScriptor 贝斯/鼓替换入口（本机研究版）

先使用现有方案生成Noto Type1、480 ticks、单一120 BPM且带独立bass/drums轨的基线MIDI；然后提供该基线所用的原始音频及其SHA，运行：

```sh
.venv/bin/python scripts/run_muscriptor_bass_drums.py \
  --audio /音频路径/歌曲.mp3 \
  --baseline /本地Noto基线.mid \
  --baseline-audio-sha256 原始音频的SHA256 \
  --output-dir outputs/runs/新任务
```

该命令本地FFmpeg解码成16kHz单声道、CPU 2线程运行MuScriptor Medium、固定指定钢琴/木吉他/清音电吉他/电贝斯/弦乐合奏/鼓、提取贝斯和鼓，并替换基线的两轨；无目标轨或格式、输入/资源哈希不符时失败，不覆盖输出。提供的原音频SHA仅核对音频是否与调用者所填一致，不能自行证明基线来源或时间线正确。输出总长度与输入差超过0.1秒会拒绝，但同长度音频也可能不对齐；调用者需保证基线来自同一音频、起点相同。

此为本机实验入口，并非完整自动从任意MP3生成六轨的单命令；用户须先准备其他四轨和基线。默认固定读取本机 engine SHA 6a9c98a1fc5d98b276bdc9e2f1fed986080057dbb5ace0566aab92c681355b00 和模型文件 SHA 3850cc9e5b436b17a09bd25b8f2615cb3366ab96a71e7b50f73a793a917fdf03；模型和编译产物不进Git，本哈希绑定当前机器，其他环境重建后需重新核验并更新代码中的绑定才能运行。

engine来自 muscriptor.cpp 34a01513f3edfacf21fba7849859b703a6e2a9df，本目录 engine.patch.b64 是本轮使用源码差异的base64；解码后可用于核对。GGUF权重使用 MuScriptor Medium，仓库说明权重 CC BY-NC 4.0，不可默认商用；联网下载及授权需遵守上游许可。模型未预测力度，自动入口固定为80。原始模型输出及报告保存在output-dir，私有音乐与权重不上传。

后续运行报告记录实际送入模型的解码WAV SHA、采样率和帧数（临时WAV在运行结束后清理）。
