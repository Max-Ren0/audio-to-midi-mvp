# 贝斯逐步改动计划

用户已授权根据诊断逐步修改并评估。全局流程：固定Demucs贝斯/已验证pYIN帧 → 置信度局部扩展（C）或独立音频起音引导转写（O）→ 通用清理/MID → 与固定标准评测 → 对比新增命中/误报/丢失 → 冻结最优 → 独立只读验证。

先登记12个候选，不看标准生成：原版1、C独立3、O独立2、C×O组合6。参数见实验登记.json。C保持voiced/能量/同音高，不把全段0.2统一降低；O以音频起音定开始，在随后320ms内按置信度加权投票判音高，至少80ms音高支持，按下一起音截断，允许延迟离线识别。O2仅用音频包络局部谷值回溯，最多96ms，无固定减时移或参考改时间。

保留原默认接口，新行为放独立研究模块，缓存重建CLI校验输入/帧/配置，不读标准。先测试未实现失败，再实现；生成与评测分离。音符/时间、置信度扩展/起音来源逐项保存。空候选保留明确空对照，不伪造音符。

所有步长/参数是开发假设，不保证提分。以固定50ms作为正式评分；诊断可看其他容差但不选其为新成绩。原鼓/钢琴/其他四类不变，六轨直接拷贝其他轨消息与ticks，仅更换贝斯轨并复核。音色试听仅由MIDI渲染。权重/音频/批量产物留本地，Git保存程序、报告和校验。先固定提交再独立验证，最后main/语义研究标签/推送。
