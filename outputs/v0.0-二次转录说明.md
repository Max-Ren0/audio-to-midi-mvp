# v0.0 二次转录与音色交付

本轮使用用户新提供的AudioTrimmer MP3，按质量优先重做。当前是实验结果，需用户听辨；文件检查通过不等于转谱准确。

## 路线

- Demucs4.0.1 htdemucs_6s分离六类音频，CPU2线程，segment6秒、overlap0.25、shifts1。
- pYIN分别处理人声与贝斯，加入起音边界以保留同音重复节奏。
- BasicPitch0.4.0 ONNX处理钢琴，onset0.65、frame0.4、最短120ms。
- YourMT3分别处理吉他、鼓、other；仅保留对应的吉他、鼓、弦乐标签，不强行改类别。
- MIDI为Type1、480PPQ，每轨写Bank Select、Program Change、instrument_name及平衡音量。
- TinySoundFont0.3.7配GeneralUser GS2.0.3离线渲染WAV，全局峰值归一化约0.9，不混原曲、不启动音频设备。

## 实测

输入解码60.0304375秒；最终重转录及首次渲染142.78秒，复用的音频分离另约40秒，不能将142.78秒当完整单次总耗时。用户已批准本轮放宽三倍时长，生产默认transcribe限制不变。

591个音符：钢琴227、木吉他70、电吉他1、贝斯51、鼓56、弦乐71、人声旋律115。电吉他候选太少，不称七类已可靠完成。

监测峰值：DSP约0.77GiB，三个YourMT3进程分别约2.63/2.54/2.57GiB，均尝试1次。最初分离阶段未监测峰值，不补造数值。

59项自动测试通过；真实产物复读检查通过。回归覆盖同音重复、音色与Bank信息、中性弯音渲染、复用音频的来源哈希。无人工标注和Logic实机验收，准确率未知；模型解码与钢琴串音风险仍在。

## 复现

```sh
sh scripts/setup_quality.sh
.venv/bin/audio-midi prepare
```

实验依赖只作ONNX/离线音频用途，跳过未使用的TensorFlow/CoreML/PyAudio组件；版本在requirements-quality.txt，隔离Demucs环境在requirements-separation.txt。再次单独uv sync可能移除这些额外实验依赖，需重新执行准备步骤。

另将固定资产放入work目录（不提交Git）：

- https://dl.fbaipublicfiles.com/demucs/hybrid_transformer/5c90dfd2-34c22ccb.th
  保存为work/models/demucs/hub/checkpoints/5c90dfd2-34c22ccb.th。
  SHA256：34c22ccb381c6f9fdbf324f04e1e2fe21aaaf293f5ded163a162697ff9a02ddd。
- https://raw.githubusercontent.com/mrbumpy409/GeneralUser-GS/684543d5e5efaef08d02be50dcda8d552478fa60/GeneralUser-GS.sf2
  保存为work/models/GeneralUser-GS.sf2。
  SHA256：9575028c7a1f589f5770fccc8cff2734566af40cd26ed836944e9a5152688cfe。

```sh
.venv/bin/python scripts/reprocess_split.py "/完整路径/输入.mp3" --output-dir outputs/runs/新结果目录
```

默认实验900秒，按阶段限制内存，已有目录拒绝覆盖。复用--stems需匹配输入和六个WAV的哈希来源记录，不能仅凭时长复用。
