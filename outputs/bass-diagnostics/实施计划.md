# 贝斯诊断实施计划

2026-10-16，用户已确认补诊断记录和逐音错误归因。本轮只诊断当前0–60，固定鼓/钢琴和现有贝斯MIDI，无新模型、分离、调参、训练或外部服务。

流程地图：已校验当前输入和Demucs bass.wav → 同参数pYIN重跑并记录帧 → 记录过滤/补洞/平滑/切分/删除 → 校验重建事件与原贝斯MID → 独立标准评测及逐音证据 → 报告。

1. 给原contour流程增加可选trace，不改变默认输出；先用合成帧测试记录完整性、短音/空隙/平滑/再弹奏边界。
2. 新增独立归因模块，固定.9995/.14映射、同音高50ms最大一对一匹配。将匹配对、每一个FP/FN、放宽时限和八度候选、各帧过滤与切分证据列出；诊断候选不改分、不当作因果证明，不独占分配同一邻近事件。
3. 输入/分离收据/参考/基线/源码哈希绑定；一次pYIN回放限CPU2、6GiB、1800秒、失败不自动重复。只复用当前60秒原Demucs bass，不访问历史60–120。写新的本地目录，不覆盖现有文件。
4. 逐帧NPZ/CSV、局部音频证据保留本地；Git保存代码/紧凑逐音证据/评分/报告/校验。没有独立原贝斯音频，不计算SDR，不把“前端未出现”直接归罪分离器。
5. 核对原贝斯/鼓/六轨哈希未变、测试、冻结提交；之后独立只读验证子agent审查真实结果，处理发现，再同步GitHub。
